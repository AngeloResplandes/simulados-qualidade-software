Product: Página estática de estudo para os simulados da disciplina Qualidade de Software (Prof. Vitor Castro).

Audience: O próprio estudante, revisando os quatro módulos antes da prova.

Primary job: Responder as questões de cada simulado e revisar os flashcards, no texto original, para conferir o gabarito.

Observable success: Cada questão e cada flashcard dos quatro markdowns aparece completo; o estudante escolhe (ou escreve), confere o gabarito original e avança; o visual permanece escuro e quieto em desktop e no telefone.

Real content and clearly labeled samples: Todo o enunciado, alternativas, frente/verso dos flashcards e gabaritos vêm de `docs/simulados/Simulado – Módulo 1: Fundamentos de Qu.md`, `docs/simulados/Simulado – Módulo 2: Normas.md`, `docs/simulados/Simulado – Módulo 3: Metricas.md` e `docs/simulados/Simulado – Módulo 4: CMMI.md`. Nenhum item novo. A oferta conversacional no fim do Módulo 1 (“Quer que eu gere mais questões…”) não é questão nem flashcard e fica de fora. Rótulos de interface (Conferir, Próxima, Virar) são chrome, não conteúdo de estudo.

Existing design system: Nenhum. O repositório só tinha os quatro markdowns.

User constraints: Usar as questões e os flashcards sem tirar nem acrescentar matéria. Visual dark mode e minimalista. Uma página para testar conhecimentos.

References and source: Os quatro arquivos de simulado listados acima. Pedido do usuário em 22/10/2026.

Assumptions: HTML/CSS/JS estático basta (não há stack). Discursivas não são corrigidas automaticamente: o estudante compara com o gabarito. Persistência local de progresso é apoio de uso, não conteúdo novo.

Open material decisions: Direção visual delegada pelo pedido (dark + minimalista); a variante específica “Caderno noturno” foi escolhida na direção.
